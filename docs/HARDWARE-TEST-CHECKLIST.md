## 协作分工

用户负责接线、主机首次启动和测试对象选择；助手负责电脑侧准备、管理操作、校验、诊断及记录。下面是具备对应条件后的分工，不表示现在已经连接设备或获准执行全部写入。

- **助手可独立准备**：开发包与摘要核对、电脑隔离目录和测试文件、电脑自动化检查、结果模板、日志分析与缺陷修复（P01 / P02 的电脑部分）。
- **用户首次协助**：连接 USB 和供电，必要时手动复制已核对的 NRO，在 Switch 完整应用模式启动配套；选定允许修改的测试游戏、用户、槽位，并提供自有测试包及独立备份（P00 / P01 / P03）。
- **连接成立后助手主做**：电脑端启动与连接诊断，设备 / 游戏 / 容量读取；SD 测试目录内的传输和摘要校验；存档备份 / 校验 / 拖出；指定测试对象的恢复、安装预检 / 安装、导出、来源检查和二期禁用状态检查（R02–R04、F01–F04、S01–S06 的管理部分、I01–I06、G01–G03）。写入只在已确定的测试范围内开展。
- **用户按步骤配合**：主机 X / B 与首次重开、实际拔插、休眠唤醒（R01 / R05–R07 的主机部分）；进入游戏生成 A / B 进度，保存后退出；恢复或安装后再次启动游戏并提供实际画面（S01 / S03–S05、I02 / I03 / I06 的游戏部分）。助手据画面和备份记录共同判断，不能只凭电脑任务状态判成功。
- **后续另行安排**：写入 / 安装中断、供电中断和空间不足等故障注入（L01 / L02）。跨平台迁移与原生 HOME 隐藏仍缺实现或准入，双方都不通过绕过保护来测试。

自动测试台的最近项目记录仍包含 USB 手柄在休眠 / 重新入座后未恢复就绪的问题；新版固件与配套没有完成新一轮真机验收。本轮尚未检查实时连接，因此不能承诺当前能代替用户操作 Switch。以后确认可靠的新画面采集及按键 / 松键通道后，可再接管部分主机重复操作。

SwitchDesk 的 USB 管理测试不必等待自动测试台修复：用户手动启动配套后，可以先由助手完成电脑侧读取与管理测试。需要真实鼠标拖放、键盘焦点或桌面界面操作的项目会占用电脑前台；协议读取、文件校验和日志整理尽量后台完成。

## 1. 第一轮：启动、连接与只读信息

先完成本组，再进入文件和存档测试。

- [ ] **R01：启动与退出。** 在 Switch 完整应用模式打开配套，电脑启动 SwitchDesk；按 X 查看连接详情，按 B 退出，再重新打开。
  - 通过标准：无崩溃、无卡死；版本可辨认，退出后可以重开。
- [ ] **R02：USB 连接。** 直连 USB，在“连接诊断”查看设备名称、握手和能力。
  - 通过标准：识别为 SwitchDesk PC，型号、HOS、Atmosphère 与当前 sysMMC / emuMMC 环境可核对；不要把缓存当作刚读取的在线信息。
- [ ] **R03：游戏列表。** 选 3 个有代表性的游戏，查看名称、大小、本体 / 更新 / DLC；切换搜索、来源和网格 / 列表。
  - 通过标准：与主机实际安装情况一致；不能读取的组件给出提示，不据此自动删除或重装。历史上有 1 条不可读记录，需要单独记录当前表现。
- [ ] **R04：容量。** 对照主机当前环境的存储信息，查看 SD 与当前系统用户分区容量。
  - 通过标准：总量和剩余量合理、环境正确；明显差异记录数值，不能混用另一套系统环境。
- [ ] **R05：空闲拔插。** 确认没有任务运行后，拔掉 USB，再插回；先做 3 次顺畅性检查，后续累计到路线要求的 20 次。
  - 通过标准：断开后明确标离线并保留原同步时间；重连后能重新读取，不一直显示连接中。
- [ ] **R06：空闲休眠 / 唤醒。** 无任务时让主机休眠并唤醒，再检查管理连接，必要时正常重开配套。
  - 通过标准：连接状态真实、操作可恢复；是否需要重开、是否稳定恢复如实记录，不要求假装无缝恢复。
- [ ] **R07：退出和旧配套边界。** 无任务时分别正常退出电脑端、主机端并重开；若另测旧 0.2.4，检查新功能是否提示能力不足。
  - 通过标准：界面不残留在线状态；旧配套不被误认为支持新迁移 / 新管理安装能力。

**这一轮通过，证明启动与只读可用；不能据此勾选备份恢复或安装成功。**

## 2. 第二轮：SD 文件小范围读写

只操作 `/SwitchDeskTest`，不用系统目录验证删除保护。

- [ ] **F01：创建与上传。** 在 SD 新建测试目录，上传一个文本文件、一个图片或二进制文件，以及一个含中文名、子目录和空目录的文件夹。
  - 通过标准：目录和文件齐全，中文名及空目录正确；任务完成状态与实际文件一致。
- [ ] **F02：下载与校验。** 将上传的文件 / 文件夹下载到另一个电脑目录，对原文件和回传文件分别计算 SHA-256。
  - 通过标准：对应文件大小、SHA-256 一致。只确认“能打开”不算完整校验。
- [ ] **F03：冲突、重命名与删除。** 对测试副本制造同名文件，查看提示；重命名并重新进入目录；仅删除本轮生成的测试文件。
  - 通过标准：冲突处理清楚，名称与列表同步，取消操作不误删其他文件。
- [ ] **F04：取消文件传输。** 用较大但可丢弃的普通测试文件开始传输，通过界面取消，再检查目标文件和任务。
  - 通过标准：未完成文件不被当作完整成功文件，后续连接可继续使用。此项不等于存档写回或安装可安全取消。

可在电脑 PowerShell 中分别运行，比较输出的 `Hash`：

```powershell
Get-FileHash -LiteralPath '原文件的完整路径' -Algorithm SHA256
Get-FileHash -LiteralPath '下载回电脑的文件完整路径' -Algorithm SHA256
```

大于 4 GiB 的普通 SD 文件复制与流式游戏安装要分开验收。FAT32 无法保存一个大于其单文件上限的普通文件，合理拒绝属于正确边界，不能标成安装引擎失败。

## 3. 第三轮：存档备份，再验证恢复

本组涉及主机存档写入，必须使用 P03 的专用用户和测试进度。每次读取或恢复前先退出游戏；需要运行游戏检查时，先正常退出配套，检查后再打开配套连接。

- [ ] **S01：备份 A。** 在游戏内制造一个容易辨认的状态 A，例如某个存档点；截图记录后正常保存、退出游戏。在 SwitchDesk 选对游戏和用户，备份并校验 ZIP。
  - 通过标准：任务成功、文件存在、校验通过，记录清楚游戏 / 用户 / 环境，且没有修改主机进度。
- [ ] **S02：拖出与去重。** 将备份拖到 Windows 资源管理器的测试目录，校验该副本；游戏不变化时再次备份。
  - 通过标准：拖出的 ZIP 完整可校验；同内容不会无意义增加普通历史，来源和时间含义清楚。
- [ ] **S03：生成并备份 B。** 回游戏制造与 A 明显不同的状态 B，保存、退出，再备份 B 并校验。
  - 通过标准：A / B 均有可用副本，游戏内差异有记录，不仅靠文件修改时间区分。
- [ ] **S04：B → A。** 选择 A，核对主机 / 环境 / 游戏 / 用户，执行“恢复”；检查是否留下恢复前 B 的 Recovery 保护副本。完成后退出配套、进入游戏。
  - 通过标准：游戏确实回到 A，其他用户和未选槽位保持不变；任务没有把失败记成成功。恢复前保护副本存在且可校验。
- [ ] **S05：A → B。** 退出游戏、重开配套，使用已校验的 B 副本恢复，再进入游戏检查。
  - 通过标准：能继续 B 的进度，完成 A→B→A→B 的正常往返。另单独验证恢复前产生的 Recovery 副本可被识别、校验并用于恢复测试状态。
- [ ] **S06：自动备份。** 仅为测试用户 / 游戏启用连接后自动备份，在游戏内保存新状态、退出后重连。
  - 通过标准：新内容被备份；无变化不反复新增；不开启其他用户的自动备份，不自动清理 Recovery。

若身份或环境不符、校验失败、未生成应有的保护副本，停在该项，保留文件和“连接诊断”结果；不要重复点击恢复来试运气。不能把“任务完成”当成游戏内恢复成功。

## 4. 第四轮：安装、更新与导出闭环

前面的存档恢复验收通过后，用可重新安装的测试游戏和已匹配的自有测试包开始。本体、更新、DLC 每种格式和版本组合分开记录。

- [ ] **I01：仅做安装预检。** 点击“安装游戏”，加入一个测试包，在“整理安装清单”核对组件、本体归属、目标 SD / 当前系统用户分区及空间。
  - 通过标准：真实包内信息正确，无法识别或不适用时明确拒绝；先关闭清单一次，确认预检没有执行安装。
- [ ] **I02：安装一个独立测试组件。** 确认测试目标后只安装一项；完成后刷新组件信息，退出配套并在主机启动游戏。
  - 通过标准：版本 / 内容实际符合预期，能启动；原有测试存档可继续，不能只依据队列的成功字样。
- [ ] **I03：更新与 DLC。** 给同一测试游戏加入已匹配的更新 / DLC，核对预检、集中确认和执行结果；新版管理流程先确认配套具备所需能力。
  - 通过标准：需要的用户存档保护副本齐全；按依赖执行；安装后复读数字版本，游戏内可见新增内容且存档延续。
- [ ] **I04：自有来源。** 先测本地索引与下载缓存，再测真实 NAS / HTTPS。核对长度和 SHA-256、来源和目录时间；同版内容再次操作应如实显示无变化。
  - 通过标准：资源不符明确失败；目录不可用时显示未知或缓存来源，不伪造“已经是最新”。公网 TitleDB 的此前失败需与本轮自有来源分开记录。
- [ ] **I05：导出。** 先导出本体，再分别导出更新 / DLC，核对文件与来源清单。
  - 通过标准：导出结果完整，电脑库能登记组件；导出后重新安装和启动属于下一步独立验收，不能只靠文件存在判定。
- [ ] **I06：导出后重新安装。** 在已备份、可丢弃的测试环境中使用导出包完成重装、启动与存档检查；不为测试随意删除日常游戏。
  - 通过标准：所声明的组件能重新安装、启动和继续测试存档。卸载 / 残留清理不在当前工具的已完成功能内。

NSP / XCI / NSZ / XCZ、地区 / DLC 组合、大于 4 GiB 的流式安装均需各自留结果。不要为了复现空间不足而把日常 SD 卡填满；这项留给专门的测试环境。
