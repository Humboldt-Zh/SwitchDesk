# 自有更新与 DLC 来源

来源可以是本地目录、Windows 已连接的 NAS / UNC 目录，或用户自己的 HTTP / HTTPS 目录。根目录包含 `index.json`。HTTPS 可在界面配置用户名和密码；凭据放在 Windows 凭据管理器，不写进 JSON。HTTP 只用于无需认证的来源。

```json
{
  "formatVersion": 1,
  "entries": [
    {
      "applicationId": "0100000000000000",
      "componentId": "0100000000000800",
      "kind": "Update",
      "version": 65536,
      "size": 123456789,
      "sha256": "替换为真实文件的64位十六进制SHA256",
      "location": "updates/example.nsp"
    }
  ]
}
```

示例 ID 与大小为占位，不是游戏信息。`kind` 为 Base / Update / DLC / DataPatch，版本必须显式提供数字，0 也是合法版本。每个索引条目对应一个实际独立组件；无法精确筛选的混合包拒绝安装。界面“从安装包生成索引”调用主机解析真实清单，再计算文件摘要，不根据文件名生成游戏身份。

HTTP 根地址以 `/` 结尾，例如 `https://nas.example/switch/`，索引位置为 `https://nas.example/switch/index.json`。下载地址必须在相同协议、主机、端口和目录内，禁止跳转及路径穿越；需要 CDN 时应直接配置最终目录。

服务器提供强 ETag，并正确响应 Range / If-Range / Content-Range 时可以续传。弱 ETag、无标识或资源变化时重新下载；下载后一定核对长度与 SHA-256。下载缓存不是内容授权来源，实际包仍需主机再次解析。

“检查更新”显示 TitleDB 目录的来源和获取时间，没有记录时显示“目录暂无记录”。目录有记录而用户没有包时只展示信息；本工具不会代为寻找公网游戏下载链接。没有连接主机也可下载并校验缓存，安装前再核对包内身份、依赖、空间和当前环境。

管理安装可勾选同一游戏的多个组件，一次确认后先保护所有用户存档，再按依赖逐项安装，最后重新读取每个数字版本；同版无变化、真正升级和失败分别记录。混合包仍不进入清单，多个独立包按更新 → DLC → DLC 更新排序。不会自动升级主机系统或降级游戏。断线后先查询操作状态和实际版本，不自动重复写入；已完成结果保留，未开始项目重新预检后再继续。
